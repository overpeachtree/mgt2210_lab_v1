Lab 2: From Automation to Agentic Research

Moving from Rule-Based Matching to Semantic Judgment

In Lab 1, we built a deterministic research automation system. The system could discover Markdown files, identify a person by name, search the web, rank candidate results using predefined rules, update a research file, and record the resulting change in Git.

The automation worked well when the task could be expressed through explicit procedures. However, one research subject exposed an important limitation.

The name Charles Henry Bennett refers to more than one notable individual. Our intended research subject was Charles H. Bennett, the physicist and information theorist associated with IBM Research and quantum information science. Yet the Phase I search also returned material concerning Charles Henry Bennett, a nineteenth-century British illustrator.

The automation did not malfunction. It followed the rules exactly as written.

The problem was that matching a name is not the same as identifying a person.

This lab introduces a language model as a new system component. Instead of asking Python to make every decision using fixed keyword rules, we allow a large language model to evaluate contextual evidence and return a structured judgment.

A Failure That Reveals a Design Problem

The Phase I workflow searched for a person's name together with terms such as interview and podcast. Search results were then scored according to predefined keywords.

For a relatively distinctive name such as Stephen Wolfram, this approach can work reasonably well. For an ambiguous name, however, the weakness becomes clear.

Consider two possible search results:

Table 2.1 Two Search Results Sharing the Same Name
Search Result Actual Identity
Charles H. Bennett discusses quantum information and IBM Research The intended physicist and information theorist
Charles Henry Bennett sketches and Victorian illustrations A nineteenth-century illustrator

A string-matching system sees the same or similar name in both results. A human researcher immediately notices that the surrounding context describes two different people.

The distinction requires more than syntax. It requires interpretation.

From Syntactic Matching to Semantic Judgment

Phase I relied primarily on syntactic signals. Examples include whether a particular string appeared in a title, whether a filename ended in .md, or whether a search result contained the word podcast.

Phase II introduces semantic judgment. The system now considers contextual information such as occupation, employer, research field, collaborators, historical period, and intellectual contributions.

For Charles H. Bennett, the intended identity can be described as: 

Name: Charles H. Bennett

Identity:
Physicist and information theorist associated with IBM Research.

Known for:
- quantum information science
- quantum cryptography
- reversible computation
- quantum teleportation
- work with Gilles Brassard
- BB84
- the 2025 ACM A.M. Turing Award

Do not confuse with:
Charles Henry Bennett, the British Victorian illustrator
who lived from 1828 to 1867.

This information is not simply converted into another collection of rigid if statements. Instead, it becomes contextual information supplied to a language model.

The Phase II Architecture

The architecture now contains two distinct computational roles.

Python remains responsible for control. It performs the search, collects results, sends information to the language model, validates the returned structure, and determines what may be written to the research file.

The language model is responsible for judgment. It evaluates whether each candidate source appears to refer to the intended person and whether that source is useful for the research objective. 

Research subject
      ↓
Web search
      ↓
Candidate results
      ↓
Identity context + candidates
      ↓
Language model
      ↓
Structured judgment
      ↓
Python validation
      ↓
Markdown update

This separation is intentional.

The language model is not given unrestricted permission to rewrite the repository. It proposes a structured evaluation. The deterministic program decides how that evaluation is used.

Using an LLM as a Judgment Layer

The Phase II prototype uses the Gemini API. A web search first produces a set of candidate results. Each candidate contains information such as: 

{
    "title": "...",
    "url": "...",
    "snippet": "..."
}

The candidate results are then combined with a description of the intended identity and sent to the language model.

The model is asked to answer several questions for every candidate:

  1. Does this result refer to the intended person?
  2. Is the result a useful research source?
  3. How confident is the model in the identity judgment?
  4. What evidence supports the decision?

This is fundamentally different from the Phase I scoring system.

Phase I asked: 

Does the result contain the word "interview"?

Phase II asks: 

Given the identity description and contextual evidence,
does this source actually refer to the intended person?

Example

Consider a search result describing sketches created by Charles Henry Bennett in the nineteenth century.

A deterministic system might observe that the correct name appears and continue processing the result.

The Phase II language model can instead consider the surrounding evidence:

  • Victorian period
  • illustration
  • sketches
  • nineteenth-century dates

and compare that evidence with the intended identity:

  • IBM Research
  • physics
  • quantum information
  • Gilles Brassard

The model can therefore conclude that the result refers to a different person even though the name matches.

Why Structured Output Matters

A language model could simply return a paragraph explaining its conclusions. That would be readable by a person, but it would make the next programmatic step unnecessarily difficult.

Instead, Phase II requests structured output.

A simplified result might look like: 

{
  "candidate_number": 3,
  "same_person": false,
  "useful_source": false,
  "confidence": 0.99,
  "reason": "This result concerns the Victorian illustrator,
             not the IBM quantum-information researcher."
}

Another candidate might return: 

{
  "candidate_number": 5,
  "same_person": true,
  "useful_source": true,
  "confidence": 0.98,
  "reason": "The source discusses Bennett's work in quantum
             information and his collaboration with Gilles Brassard."
}

Structured output creates a bridge between probabilistic AI reasoning and deterministic software.

The language model handles ambiguity. Python receives predictable fields that it can inspect and act upon.

Probabilistic Judgment Inside Deterministic Control

This design illustrates an important architecture for contemporary AI systems:

Use probabilistic models for judgment while preserving deterministic software for control.

The LLM may decide: 

same_person = true
confidence = 0.97

but Python still decides what happens next: 

if item["same_person"] and item["useful_source"]:
    accepted.append(item)

The model therefore contributes intelligence without receiving unrestricted control of the system.

Table 2.2 Division of Responsibility in Phase II
Component Responsibility
Web search Retrieve candidate information.
Language model Interpret context and make semantic judgments.
Structured schema Constrain the form of the model's response.
Python Validate, filter, and control downstream actions.
Markdown Store accepted research information.
Git Record changes and preserve an audit trail.

The Role of the API

The language model does not run directly inside the Python script. The script communicates with a model service through an application programming interface, or API.

Conceptually: 

Python program
      ↓
API request
      ↓
Gemini model
      ↓
API response
      ↓
Python program

The API separates the application from the model provider. The research system sends information in a defined format and receives a response.

This distinction is important because the overall architecture does not inherently depend on Gemini. Another compatible language-model provider could eventually replace it.

The model provider is therefore a service component inside a larger information system.

Protecting API Credentials

Using an external model service introduces a new security concern: API credentials.

An API key should not be written directly into source code: 

GEMINI_API_KEY = "my-secret-key"

If committed to a public GitHub repository, that credential could become visible to other users.

Instead, GitHub Actions can store the credential as a repository secret: 

GEMINI_API_KEY

The workflow makes the secret available to the program at runtime without storing its value inside the repository.

This introduces another important systems concept: separate configuration and credentials from application code.

Why Call This Agentic Research?

The Phase II system differs from the Phase I automation because not every decision is explicitly encoded in Python.

The system is given a research objective and contextual information. A language model then exercises bounded judgment concerning the evidence it receives.

This is why Phase II can reasonably be described as agentic research.

However, the system is still deliberately constrained.

It does not independently choose from many tools. It does not repeatedly plan new actions. It does not decide to search again when evidence is insufficient. It does not maintain sophisticated memory across runs. It does not freely modify arbitrary repository files.

Instead: 

Python controls the workflow.
LLM supplies judgment.
Python controls the action.

This makes Phase II an intermediate step between conventional automation and a more complete agent harness.

Moving Beyond Identity Disambiguation

Identity classification is only the first semantic task.

Once the system can reliably distinguish the intended Charles H. Bennett from unrelated individuals, the same judgment layer can be expanded.

For example, the language model could classify each accepted result into categories: 

INTERVIEW
PODCAST
TALK
PROFILE
AWARD_OR_NEWS
REFERENCE
OTHER

A future version could then maintain separate sections in the research file: 

Latest Interviews and Podcasts

Supporting Profiles

Awards and News

Reference Sources

The model could also evaluate publication dates, detect duplicate sources, extract themes, or create concise summaries.

Each additional capability increases the system's ability to operate on meaning rather than simple textual patterns.

What Phase II Does Not Solve

Adding a language model improves semantic interpretation, but it also introduces new problems.

The model may classify a source incorrectly. Confidence scores are not guarantees. Search results may contain incomplete information. The model may receive insufficient context. An API call may fail. A model provider may become temporarily unavailable. Different models may produce different judgments.

More importantly, as the model is given more freedom to choose actions, the surrounding system must become more sophisticated.

Questions begin to appear:

  • Which tools may the model use?
  • What files may it modify?
  • How many times may it search?
  • When should it stop?
  • What happens when a tool fails?
  • How should state be preserved between actions?
  • Which actions require human approval?
  • How can the agent's actions be evaluated?

These are not primarily questions about the intelligence of the model.

They are questions about the environment surrounding the model.

That environment is the focus of Phase III.

From Agentic Research to an Agent Harness

The progression now looks like this: 

PHASE I
Automation

"We know the procedure.
Execute it repeatedly."

        ↓

PHASE II
Agentic Research

"We know the goal.
Use bounded semantic judgment."

        ↓

PHASE III
Agent Harness

"Create an environment in which an agent can
use tools, maintain state, act repeatedly,
recover from errors, and remain under control."

Phase I moved work from humans to software.

Phase II moved selected judgments from explicit rules to a language model.

Phase III will focus on how increasingly autonomous behavior can be organized, constrained, observed, and governed.

Key Terms and Definitions

Agentic Research
A research process in which an AI model is given a research objective and exercises bounded judgment when evaluating, selecting, or interpreting information.
Large Language Model (LLM)
A machine-learning model trained on large collections of language data that can generate and interpret text and perform a range of language-based reasoning tasks.
Semantic Judgment
Evaluation based on contextual meaning rather than only literal strings or predefined patterns.
Identity Disambiguation
The process of determining which real-world entity a name or reference corresponds to when multiple entities may share similar identifiers.
Structured Output
A model response constrained to a predefined data structure so that software can reliably interpret individual fields.
Schema
A formal description of the structure, fields, and expected data types of an information object.
API
An application programming interface that defines how one software system can request services or data from another system.
API Key
A credential used by an application to authenticate itself when calling an external service.
Secret
Sensitive configuration information, such as an API key, that should be stored separately from application source code.
Probabilistic System
A system whose outputs may vary and are expressed in terms of likelihood rather than being completely determined by fixed rules.
Deterministic Control
The use of explicit program logic to constrain how probabilistic AI outputs are converted into system actions.
Confidence Score
A numerical representation of how strongly a model or system supports a particular classification or judgment. A high confidence score does not guarantee correctness.
